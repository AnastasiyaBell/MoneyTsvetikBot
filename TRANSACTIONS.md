# Новые типы операций

Изменения подготовлены в коде. Для включения в работающем боте обновите Google Apps Script и Cloudflare Worker.

## Установка обновления

1. Сделайте копию Google-таблицы через «Файл → Создать копию».
2. Замените код Apps Script содержимым finance_bot_backend_google_sheets.js, сохраните.
3. При желании запустите migrateTransactionColumns из редактора: она добавит недостающие заголовки во все DataYYYY. Можно не запускать вручную: проверка выполняется при чтении и сохранении через backend.
4. Обновите существующее развёртывание веб-приложения Apps Script на новую версию, сохранив URL /exec.
5. Обновите Worker командой npm run deploy. Если URL Apps Script изменился, обновите SHEET_URL.
6. Откройте «🧾 Транзакция» в Telegram и проверьте новые типы. Сначала обновляйте backend, затем Worker.

## Использование

- 💸 Расход: категория расходов → счёт списания → сумма и описание.
- 💰 Доход: категория доходов → счёт поступления → сумма и описание. Знак плюс не требуется. Категории: Зарплата, Подработка, Сдача квартиры, Подарки, Социальное, Возврат налогов, Другое.
- 🔄 Между своими: счёт списания → счёт поступления → суммы. Одинаковые счета разрешены для обмена наличных.
- ↩️ Мне вернули: категория расходов → счёт поступления → сумма и описание. Уменьшает расходы категории на дату возврата, не считается доходом.

Для обычных операций: 25 продукты, 500руб продукты, 20лир автобус, 25дол кафе. Можно использовать десятичную точку или запятую.

Переводы:

| Ввод | Списание | Поступление |
| --- | --- | --- |
| 100 / 108дол | 100 EUR | 108 USD |
| 100дол / 9500руб | 100 USD | 9500 RUB |
| 100дол / 95 | 100 USD | 95 EUR |
| 100 | 100 EUR | 100 EUR |
| 100лир | 100 TRY | 100 TRY |

Без приписки каждая сумма означает евро. После суммы поступления можно добавить описание: 100 / 108дол обмен.
Тип, категория и счета остаются выбранными для следующего сообщения. Чтобы поменять их, снова откройте «🧾 Транзакция».

## Столбцы и старые данные

Первые девять столбцов сохраняются в прежнем порядке:

Date | Type | Amount | Currency | Amount_EUR | Category | Description | Account | User

Справа добавляются отсутствующие заголовки:

| Столбец | Значение |
| --- | --- |
| From_Account | Счёт списания у расхода и перевода |
| To_Account | Счёт поступления у дохода, возврата и перевода |
| Transfer_In_Amount | Фактически полученная сумма, только у перевода |
| Transfer_In_Currency | Валюта полученной суммы, только у перевода |
| Transaction_ID | Постоянный идентификатор записи |

Amount и Currency у перевода означают сумму и валюту списания. Account сохранён для совместимости: у расхода и перевода это счёт списания, у дохода и возврата — счёт поступления.

Миграция добавляет только заголовки; старые строки, суммы, формулы и порядок первых девяти столбцов не переписываются. Повторный запуск не создаёт дубликаты заголовков. Новые поля старых строк остаются пустыми; ID присваивается старой записи при просмотре для удаления. Новые операции сразу получают ID. Неожиданный порядок исходных столбцов вызывает ошибку, а не автоматическую перестановку данных.

Переводы, раньше записанные расходом и доходом, автоматически не переклассифицируются. Отчёт Power BI в этом изменении не обновлялся: его меры должны исключать transfer и вычитать refund из расходов. В аналитике Telegram это уже реализовано.

Подтверждение удаления содержит ID конкретной операции. Повторная доставка одного Telegram update не создаёт вторую строку в таблице; подтверждения и уведомления при повторной доставке могут повториться.

## Проверка кода

node transactions.test.mjs

Тесты используют имитацию Telegram, KV и Google Sheets; реальная таблица и работающий бот не изменяются. Проверяются форматы сумм, обмен наличных в наличные, категории доходов, аналитика с возвратами, сохранность старых строк, повторная миграция, защита от повторного сохранения и удаление по ID.
